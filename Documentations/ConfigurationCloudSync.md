# 配置文本的 iCloud 同步

配置页的 **iCloud Configurations** 区域复用现有 CloudKit 私有数据库、加密 payload 和全局 **iCloud Sync** 开关。不是 iCloud Drive 中可浏览的普通文件；配置可以继续用现有导入/导出入口交换。

## 使用

1. 在系统登录 iCloud，并开启 App 的 iCloud Sync。
2. 编辑停止约两秒后，草稿自动保存到本机同步队列；也可以点 **Save for iCloud Sync** 立即入队。即使草稿语法尚未完成，也保留完整原文。
3. 成功应用配置后，同步单独的 **Applied** 文本副本；**Draft** 继续保存当前编辑内容。启动时会补入队已有本地草稿和活动配置。
4. 其他设备收到完整副本后，配置页按设备分别列出 Draft / Applied。点击副本并确认后载入编辑器，再按 Apply 在本机编译并启用。
5. **Refresh iCloud Configurations** 请求拉取云端变化。保存入队不等于服务器已确认；实际上传/下载由 CKSyncEngine 按网络、账号、系统调度和配额执行。关闭开关停止云端传输，本地仍可保存并排队。

同步不改动活动版本指针、VPN 连接、应用状态回执或 CA 私钥。规则集与脚本来源保留在原文中；在另一设备应用时重新验证和读取，源缓存及本地 file URL 的授权不会随文本同步。自带 App 的 CloudKit container 必须与签名和 Apple 开发者配置一致，沿用现有工程的 entitlement。

## 并发编辑与恢复

每个安装使用独立的本地身份，草稿与已应用文本各有一个槽位；两个设备的并发编辑保留为两份副本，不做文本自动合并。云端变化只更新副本列表，不覆盖当前编辑器，也不自动应用到运行中的隧道。

载入云端文本前将当前编辑内容原子备份为本地 `before-cloud-load.txt`。备份失败时拒绝替换编辑器；**Restore Draft Before iCloud Load** 可以恢复，退出并重开 App 后仍可读取。此备份保留最近一次云端载入前的内容，不是无限历史。应用历史与内核运行包继续由本机版本系统维护。

## 大文件与传输完整性

沿用配置的 16 MiB 上限。每个副本分为 256,000 字节的块，每个 JSON payload 小于 SyncStore 的 900,000 字节限制；清单记录块数、逐块 SHA-256、整文摘要、总长度和更新时间。UTF-8 解码发生在完整重组之后，支持跨块的 Unicode 字符。

块与清单可以乱序到达。缺块、混合版本、损坏、大小不符或无效编码时不展示不完整副本；本次会话已读取的完整副本继续保留，直到新版完整。每个安装的每个槽位最多 66 个固定块，不随每次按键新增无限历史记录。未变化的块不重复排队。

所有同步数据使用新集合 `configurationDocuments`，与原有 `configurations`（代理节点）分离。现有 CloudKit Record Type 和加密字段不变，不需要新增 payload 字段。

## 验证状态

新增测试覆盖大于单条 CloudKit 记录限制的 Unicode 原文、空/无效草稿、缺块/混合版本、损坏校验、设备与 Draft/Applied 隔离、缩短文档后残留块、半同步时保留完整副本，以及编辑器备份/恢复和备份失败拒绝载入。

当前环境只有静态语法/工程检查，没有 Swift/Xcode。未执行单元测试或真实 iCloud 验收。需在签名正确且使用同一 iCloud 账号的两台设备上验证：双向同步、离线编辑再联网、并发修改、超过 900 KB 的文本、开关重启、应用重启、备份恢复，以及未完成下载时不显示半份配置。
