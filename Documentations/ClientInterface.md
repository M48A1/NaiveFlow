# iOS 客户端界面

底部固定为首页、策略组、设置三个 Tab，使用系统蓝、动态系统背景和原生 SwiftUI 导航。

- 首页依次为“我的配置、运行控制、出站模式、PROXY”四张卡片。配置列表和节点列表在卡片内展开，普通节点选择无需跳转。首页没有 MITM 或模块入口。
- 策略组为双列渐变卡片。支持手动选择、URL Test、Fallback、Load Balance，及组编辑、复制、排序、成员管理、图标和配色。内核状态通过只读 IPC 查询，读取状态不消耗轮询选择次数。
- 设置集中管理 DNS、网络、运行日志、请求记录、MITM、模块、证书、Hostname、通知和通用选项。不提供外观自定义、Data 或 Country Bypass。

## 配置与运行状态

`ClientModel` 管理界面会话；`ClientProfileLibrary` 原子保存命名配置文件及远程地址、模块来源、组配色等编辑元数据，路径为 App Group 的 `configurations/client-ui/profiles.json`。这些元数据不承担路由决策。

所有网络行为通过当前文本文档编译并交给 `ConfigurationPublisher` 发布。`ClientDocumentEditing` 负责定点修改键值、组成员和顺序；常规编辑保留其他文档内容。重命名节点或策略组时同步更新引用；删除仍被引用的项目时拒绝发布，显示具体原因。

`[General] default-node = Name` 明确指定 PROXY 和全局代理的默认节点，也支持代理链名称。无此字段时延续已有默认节点选择规则。每次选择都发布完整运行版本，不修改旧的独立手动设置。

保存配置草稿不会改动当前显示的运行模式或节点。应用错误会保留原运行版本；运行开关仅在已有有效配置且隧道管理器就绪时可用。

## 模块与导入

支持 Surge / Quantumult X 模块，从源文本、HTTPS 或本地文件载入。发布前解析并验证模块及脚本，将模块作为具名 `[MITM Set]` 规则写入同一配置。独立开关修改该组规则的 enabled 字段，更新模块重新解析源文件。遵循当前 MITM 内核的作用域、脚本和证书约束。

节点可从分享链接、Base64 节点列表、受支持的订阅格式或原生配置载入。HTTP 导入先验证响应；本地文件仅做内容解析。新增内容发布后才改变运行节点列表。

日志支持查看、系统分享和清除内核缓冲。通知默认关闭，用户授权后可在后台接收连接状态变化。浅色、深色和动态字体跟随系统设置。
